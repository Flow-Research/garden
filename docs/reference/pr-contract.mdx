The `PR contract` job in `.github/workflows/pr-contract.yml` runs `pnpm verify:pr`, which runs `scripts/verify-pr-contract.mjs`.

## Triggers

| Event          | Branches      | Behavior                                                                                                    |
| -------------- | ------------- | ----------------------------------------------------------------------------------------------------------- |
| `pull_request` | `dev`, `main` | Full check. Runs on `opened`, `synchronize`, `reopened`, `edited`, and `ready_for_review`.                  |
| `push`         | `dev`, `main` | Records a passing "not applicable" status, so `PR contract` appears in the branch-rule check list.          |

The job checks out with `fetch-depth: 0` because it diffs the base and head commits from the event.

## Target branch

| Target | Allowed source            |
| ------ | ------------------------- |
| `dev`  | Any branch                |
| `main` | `dev` only, for a release |

The check rejects any other target. The title must have at least 10 characters.

## Draft pull requests

A draft needs only a valid target branch and a title. The body checks run when the pull request is marked ready for review.

## Required sections

A pull request that is ready for review must contain each of these level-two headings with a non-empty body:

1. `## What changed`
2. `## Why`
3. `## Scope`
4. `## Contribution standard`
5. `## Documentation`
6. `## Checks`
7. `## Verification`
8. `## Risk and follow-up`

## Section rules

| Section               | Rule                                                                                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contribution standard | These three items are checked: "I stated the outcome and non-goals.", "I read `docs/README.md` and the relevant code, tests, and documentation", and "I reviewed the final diff and considered its wider effects." |
| Documentation         | Has a checked item that names a feature doc, architecture, design, verification, maintainer, or workflow doc, or states `Documentation: not needed` (or `not required`). |
| Checks                | Lists at least one command in code font or a `pnpm`, `npm`, `yarn`, `bun`, or `git` command.                                                                           |
| Verification          | States `PASS`, `FAIL`, or `INCONCLUSIVE` and contains the word "evidence".                                                                                           |

## Behavior changes need documentation

The check reads the changed paths between the base and head commits.

| Path class    | Paths                                                                                  |
| ------------- | -------------------------------------------------------------------------------------- |
| Behavior      | `apps/`, `packages/`, `workers/`, `scripts/`, `alchemy.run.ts`, `deploy-targets.mjs`   |
| Documentation | `docs/`, `.agents/skills/`, `AGENTS.md`, `CONTRIBUTING.md`                             |

If the diff changes a behavior path and no documentation path, the Documentation section must state `Documentation: not needed`. Otherwise the check fails.

## Run the check locally

GitHub passes the event file through `GITHUB_EVENT_PATH`. To check a saved event file, run:

```bash
pnpm verify:pr --event path/to/pull-request-event.json
```

## Limits

The check confirms that sections exist, that the required items are checked, and that commands and evidence are named. It cannot confirm that the author read a document or that the evidence is true. Normal CI proves formatting, lint, types, tests, and build output. A maintainer reviews the design, the evidence, and the user flow.
