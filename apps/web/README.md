# Garden Web

TanStack Start app for Garden's tabbed workspace, auth surface, API routes, Cloudflare Worker bindings, and local agent runtime.

## Getting Started

From the repository root:

```bash
pnpm install
cp .env.example .env
pnpm --filter @garden/db db:migrate
pnpm dev
```

The root dev command starts the MCP proxy and web app through Turbo's TUI. The web app runs at `http://localhost:3000` by default.

## Environment

Local development configuration lives in root `.env`. Web, MCP proxy, database tooling, and local scripts share it; deployed Workers use Cloudflare secrets and bindings.

Required for normal local development:

```bash
CLOUDFLARE_ACCOUNT_ID=<account that owns garden-files-staging>
DATABASE_URL=postgresql://...
BETTER_AUTH_SECRET=...
BETTER_AUTH_URL=http://localhost:3000
ENVIRONMENT=development
```

GitHub connector development also needs the GitHub app fields from the root `.env.example`.

## Commands

| Command | Description |
|---|---|
| `pnpm --filter @garden/web dev` | Start TanStack Start on `localhost` with full bindings |
| `pnpm --filter @garden/web dev:local` | Start TanStack Start directly on `localhost` with local bindings |
| `pnpm --filter @garden/web build` | Build production worker bundle |
| `pnpm --filter @garden/web typecheck` | Run TypeScript without emit |
| `pnpm --filter @garden/web worker:types:check` | Regenerate and verify Worker binding types |
| `pnpm --filter @garden/web skills:seed-builtin` | Seed bundled skills into the local workspace |

## Cloudflare Runtime

The local Worker uses `wrangler.jsonc` for Durable Objects, R2, Workflows, sandbox bindings, and service bindings. Key runtime pieces:

- `AgentDO` hosts per-agent state and WebSocket/RPC behavior.
- `FILES` and `LOADER` are R2 buckets for uploaded files and loader artifacts.
- `RUN_WORKFLOW` drives durable issue-run and automation-run execution directly from `AgentDO`.
- `MCP_PROXY` connects runtime MCP calls to local or deployed connector services.
- Sandbox container bindings are enabled in the full `pnpm dev` workflow via `wrangler.containers.jsonc`; `pnpm dev:local` skips remote bindings and containers.

Generated files such as `src/routeTree.gen.ts` and Worker types should be regenerated by the relevant scripts, not hand-edited.

## Manual Smoke

Use agent-browser for real app checks instead of unit-only coverage:

```bash
pnpm --filter @garden/web dev:local
agent-browser --session garden-smoke open http://localhost:3000/workspace
agent-browser --session garden-smoke snapshot -i -c -d 3
agent-browser --session garden-smoke console
agent-browser --session garden-smoke errors
```

Useful authenticated endpoint sweep:

```bash
curl -fsS http://localhost:3000/api/me
curl -fsS http://localhost:3000/api/workspaces
curl -fsS http://localhost:3000/api/issues
curl -fsS http://localhost:3000/api/inbox
curl -fsS http://localhost:3000/api/agents
curl -fsS http://localhost:3000/api/skills
curl -fsS http://localhost:3000/api/connections
curl -fsS http://localhost:3000/api/runtimes
```

Browser-session auth is usually easier through `agent-browser`; plain `curl` needs the same local auth cookies.
